HOW TO UPDATE THIS PROJECT FOR A NEW WPILIB YEAR
===============================================

What this project is
--------------------
This is a reusable FRC/WPILib library project for the WLED subsystem.
It is NOT year-agnostic in the strong sense, because the code directly uses
WPILib classes such as:
- edu.wpi.first.wpilibj2.command.SubsystemBase
- edu.wpi.first.wpilibj2.command.Command
- edu.wpi.first.wpilibj.DriverStation
- edu.wpi.first.wpilibj.Timer

That means this repository can be reused from year to year, but each branch
still tracks a particular WPILib year.

Current package namespace:
- frc.kauaibots.subsystems.wled

Current project identity:
- Gradle project name: wled
- Maven/group identity used by the robot composite build:
  - group = frc.kauaibots.subsystems
  - artifact = wled
  - version = 2026.0.0-SNAPSHOT

How the Gradle files came to be
-------------------------------
This project was created by extracting the WLED subsystem out of the Robot
repository into its own sibling project.

The Gradle-related files were NOT generated by running "gradle init".
They were assembled manually during the extraction.

Specifically:
- The Gradle wrapper files were copied directly from the Robot project:
  - gradlew
  - gradlew.bat
  - gradle/wrapper/gradle-wrapper.jar
  - gradle/wrapper/gradle-wrapper.properties
- settings.gradle was written manually.
- build.gradle was written manually.
- .gitignore was written manually.

Why it was done that way:
- The immediate goal was to get a standalone WLED library working quickly.
- A plain "gradle init" project would still have required WPILib-specific
  dependency setup afterward.
- Copying the wrapper avoided introducing a second Gradle-version variable
  during the extraction.

Important note:
- The wrapper copy is not the year-specific part.
- The year-specific part is the WPILib/GradleRIO configuration in
  settings.gradle and build.gradle.

Current Gradle files and what matters in them
---------------------------------------------
settings.gradle currently does these jobs:
- defines pluginManagement repositories
- points Gradle at the local WPILib Maven repository for the current year
- sets rootProject.name = 'wled'
- sets the native-headers ignore property used by the WPILib build

build.gradle currently does these jobs:
- applies java-library
- applies edu.wpi.first.GradleRIO for the current WPILib year
- sets Java 17
- declares WPILib dependencies needed by this library
- declares the explicit NewCommands dependency because the subsystem uses
  Command and SubsystemBase
- enables JUnit 5 tests
- configures WPILib test tasks for desktop execution

Current year-specific values that must be reviewed every season:
- GradleRIO plugin version in build.gradle
- the WPILib year in settings.gradle
- the wpilibNewCommands-java version in build.gradle
- the project version string

Current values as of this branch:
- GradleRIO version: 2026.2.1
- WPILib year path in settings.gradle: 2026
- wpilibNewCommands-java version: 2026.2.1
- project version: 2026.0.0-SNAPSHOT

How the Robot project consumes this library
-------------------------------------------
The Robot project includes this build using a Gradle composite build.
That means the Robot project can compile against this library directly from
source without publishing a jar first.

On the Robot side, look for:
- settings.gradle:
  includeBuild("../Subsystems/WLED") with dependency substitution
- build.gradle:
  implementation 'frc.kauaibots.subsystems:wled:2026.0.0-SNAPSHOT'

Robot-specific assets remain in the Robot repository.
This library does NOT own robot deploy assets such as bmp/gif files.
The Robot project passes file paths into the subsystem.

How to update this repository for a new WPILib year
---------------------------------------------------
Recommended model:
- keep one branch per robot/WPILib year
- examples: 2026, 2027, 2028

Recommended yearly workflow:

1. Create a new branch for the new year.
   Example:
   - branch 2027 from 2026

2. Install the new year's WPILib tools.

3. Use the new WPILib VS Code / import flow on this WLED project.
   Important:
   - WPILib import/update creates a NEW upgraded project directory.
   - It does NOT upgrade in place.

4. Compare the imported/upgraded output with this repository.
   Bring the upgraded build files back into this repo branch.
   At minimum, review:
   - gradlew
   - gradlew.bat
   - gradle/wrapper/*
   - settings.gradle
   - build.gradle

5. Reapply any intentional customizations that the WPILib import did not keep.
   In this project, that may include:
   - group = frc.kauaibots.subsystems
   - rootProject.name = 'wled'
   - explicit dependency on wpilibNewCommands-java
   - version string conventions
   - any test-task or compiler-arg settings kept intentionally

6. Update the year-specific values.
   Example for 2027:
   - settings.gradle WPILib year path: 2027
   - GradleRIO version: update to the 2027 release
   - wpilibNewCommands-java version: update to the 2027 release
   - project version: 2027.0.0-SNAPSHOT

7. Run validation inside this WLED project.
   At minimum:
   - ./gradlew test --tests frc.kauaibots.subsystems.wled.WLEDSubsystemPlaybackRegressionTest
   - ./gradlew compileJava compileTestJava

8. Update the consuming Robot project for the same year.
   The Robot repo must also be imported/upgraded for that WPILib year.
   Then confirm that the Robot project still compiles while consuming this
   library through includeBuild.

If you want a cleaner build refresh instead of keeping these Gradle files
--------------------------------------------------------------------------
It is acceptable to replace the Gradle files with a fresh "gradle init"
java-library project and then add back only the WPILib pieces this library
actually needs.

If you do that, make sure the final project still includes all of the
following:
- Java 17
- WPILib dependency resolution
- edu.wpi.first.wpilibNewCommands:wpilibNewCommands-java for the current year
- JUnit 5 test configuration
- enough WPILib test setup for desktop tests to run
- the same group/artifact identity expected by the Robot project

Regression test reminder
------------------------
This repository contains regression tests and snapshot resources that should
travel with the subsystem, not with any one robot.

Current regression test:
- src/test/java/frc/kauaibots/subsystems/wled/WLEDSubsystemPlaybackRegressionTest.java

Current snapshot resources:
- src/test/resources/frc/kauaibots/subsystems/wled/wled-prepare-image.snapshot.txt
- src/test/resources/frc/kauaibots/subsystems/wled/wled-prepare-marquee.snapshot.txt
- src/test/resources/frc/kauaibots/subsystems/wled/wled-prepare-strip.snapshot.txt
- src/test/resources/frc/kauaibots/subsystems/wled/wled-prepare-gif.snapshot.txt

Do not move these back into a robot project. They belong with the library.

Bottom line
-----------
This repository is intended to be reusable across robots, but each year branch
still tracks a specific WPILib year. The correct maintenance model is:
- one reusable repository
- one branch per year
- upgrade/import once per year
- validate the standalone tests
- then validate the consuming Robot project
